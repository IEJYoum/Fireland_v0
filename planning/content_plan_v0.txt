1. ITEMS  (direct-ish - port the numbers)
--------------------------------------------------------------------------------
Recreate the legacy item set as data. Each weapon is an item entity (def_key +
Weapon/Collider/Renderable); consumables carry an effect descriptor.

  pistol        damage 20, projectile_speed 11,  lifetime 0.7
  rifle         damage 35, projectile_speed 24,  lifetime 1.25
  sniper_rifle  damage 65, projectile_speed 40,  lifetime 1.6
  knife         damage 45, MELEE, range 1.2
  health_up     consumable, +25 health
  food          +35 hunger

V0 contract: keep the current hitscan Weapon for guns and retain
projectile_speed/lifetime as future physical-projectile data. Physical projectiles
can later be a second weapon attack style using Velocity+Lifetime+swept collision;
do not delay the content port for them. Melee (knife) = short forward arc check;
port legacy closest_enemy_in_melee_arc as a 3D cone test.

Weapons as pickups spawn in the world with Transform+Pickup; equipping is the
existing interact path. Preserve "picking up a weapon auto-equips it."

Inventory behaviour is also legacy content, not a new design:
  - capacity 8;
  - interact picks the nearest eligible item in range;
  - weapon pickup auto-equips the same entity instance;
  - one input cycles/toggles equippable inventory items;
  - food remains in inventory until the explicit eat action consumes it.
Once the origin start structure exists, the player starts unarmed and collects
the nearby pistol as in the legacy game. Do not also grant a hidden starter gun.

2. PLAYER VITALS: HUNGER, HEALTH, ARMOR, XP  (direct-ish)
--------------------------------------------------------------------------------
Add components + systems:
  Hunger(current, maximum)  decays 0.5/sec (HUNGER_LOSS_PER_SECOND). Eating food
    restores +35, capped. At hunger 0 - legacy did nothing harmful; DECISION:
    either harmless (as legacy) or start health drain. Keep legacy (harmless)
    unless the owner wants bite.
  Health heal: consumables add to current, capped at maximum.
  Xp(points): +25 per kill (legacy grant_xp). Leveling curve is open - legacy
    never consumed xp; leave xp as a counter until a use exists.
  Armor(points): damage received = max(1, raw_damage - armor), matching legacy.
    Legacy shipped with armor=0 and no armor pickup, so implement the rule and
    component now but do not invent armor content yet.
Expose all four in the snapshot (per-component to_wire) and HUD.

3. ENEMIES  (direct-ish logic, 3D movement + aim)
--------------------------------------------------------------------------------
Rebuild the legacy behaviour as a registered Think routine ("hostile" or similar)
running on enemy entities that now have Velocity/Gravity/Grounded (arch Issue 3).

Behaviour to port (legacy enemies.py):
  - Only act when the enemy is in an active region (arch Issue 2 freeze replaces
    is_on_players_screen) AND has line-of-sight/path to a player.
  - Mode roll every 1.0s: 33% EVADE (pick a nearby reachable point, move there ~1s),
    else CHASE.
  - CHASE: if farther than preferred range, steer toward the player; else hold.
    preferred range: melee -> 0.75 * reach; ranged -> clamp(4..10, weapon_range/2).
  - Steering writes CONTROL velocity (speed ~2.4 u/s, ENEMY_SPEED) through the
    shared mover; physics handles collision/gravity.
  - Fire when within weapon range and off cooldown: aim at the player's eye in 3D
    with angular spread (legacy +-0.18 rad, apply in yaw and pitch), then
    hitscan or spawn a projectile. Cooldown random uniform(0.85, 1.3)s.
  - On death: grant player xp, roll the drop pool (section 4), remove entity.

Pathing: legacy used tile BFS (has_walkable_path). In 3D v0, use line-of-sight +
direct steering (walk toward player if roughly visible, let collision slide along
walls). Real navmesh/pathfinding is deferred; do not block the content rebuild on
it.

Enemy stats: health 60 (legacy), holds a random weapon instance from the same
item system (reuse item defs). Enemy count / difficulty: legacy used
int(level_index**1.5)+1 per discrete map. With a continuous world, REINVENT as a
spawn-density model - e.g. spawn enemies per newly generated chunk, scaling count
or weapon tier with distance from origin. Keep it simple and seeded.

4. DROPS  (direct-ish odds, via the dormant Drops component + a registry)
--------------------------------------------------------------------------------
The Drops component exists but has no system - wire it now.
  - Add a drop-pool registry (behaviour-as-data): pool key -> routine(runtime,
    position, randomizer) that spawns the drop entity.
  - Port the legacy 1/3 odds pool: equal chance weapon / health_up / food.
    "weapon" drops the enemy's actual held weapon instance (legacy behaviour);
    health/food spawn fresh pickups.
  - Death handling (combat3d / a death system) reads Drops(pool=...) and invokes
    the pooled routine at the corpse position, then removes the entity.
This is also the seam for "cow drops turds", "boss drops key", etc. - new pools
are data.

Determinism: route drop rolls through a seeded randomizer owned by the runtime so
runs are reproducible (legacy had game.randomizer). Add one.

--------------------------------------------------------------------------------
5. PICKUP MODEL  (direct-ish - preserve deliberate proximity interaction)
--------------------------------------------------------------------------------
Legacy: press E, then choose the nearest item within 0.8 tiles. Health consumables
apply immediately after that interaction; they do not auto-apply merely because
the player walked over them. Weapons and food enter an inventory of capacity 8;
weapons auto-equip. If no item is in range, the same interaction may open a
nearby door.

3D rule: preserve that mechanic with a slightly larger world-space radius suited
to first person (start around 1.25 units). E chooses the nearest pickup in range;
it does not require the crosshair to be exactly over the item. Keep raycasts for
shooting. Put pickup and door priority in one interaction function so E never
triggers two things and the rule is testable in isolation.

6. WORLD CONTENT: VOXEL BIOMES + STRUCTURES  (reinvent - the big one)
--------------------------------------------------------------------------------
The legacy tile generators do not survive; their INTENT does. Rebuild as chunk
generators (arch Issue 4 provides the generator-by-key hook). Legacy map types
become biome/content flavours producing BLOCK structures.

Do not independently roll a biome for each chunk. That produces a checkerboard,
not Minecraft-like geography. Define a pure biome query:

    biome_for_chunk(world_seed, chunk_x, chunk_z) -> biome_key

V0 uses deterministic cellular regions. Divide the chunk plane into 6x6-chunk
macro cells. Give every macro cell one seed-mixed, jittered site and a biome key.
For a queried chunk, inspect the sites in its macro cell and the eight neighbours;
the nearest site owns the chunk. This produces irregular contiguous regions while
remaining simple and order-independent. The result must depend only on the seed
and coordinates, never generation order or Python's randomized hash(). A first
pass only needs plains, forest, and settled/prefab biomes. Biome boundaries remain
chunk-aligned in v0; continuity across multiple chunks is the important property.

Within the selected biome, placement is also coordinate-derived:
  - trees use stable world-cell hashes/density, including neighbouring anchors
    whose canopy overlaps the chunk;
  - buildings use seeded coarse placement cells/anchors, not "whichever chunk
    generated first";
  - generation of the same chunk in isolation must match generation after all
    neighbours;
  - keep a protected origin region for the fixed starting structure.

Block generation stays pure. It may return block data plus deterministic spawn
descriptors, but it must not directly mutate the EntityStore. The runtime
materializes each spawn descriptor exactly once using a stable identity derived
from world seed/type/coordinates. This prevents duplicate enemies or pickups if
chunk residency/eviction is added later.

Biome content:

  - Ground: flat (or gently varied) solid ground per chunk - the baseline.
  - PREFAB/SETTLED: legacy placed hollow square/L footprints with wall borders,
    half with a door, 1/10 door-buildings holding a pickup. Rebuild as hollow
    block shells (walls + floor, open or doored) from deterministic structure
    anchors, with a chance to emit a pickup spawn descriptor inside. A "door" is
    a block type that interaction can open (set_block to air) - port
    open_nearby_door as a block edit.
  - FOREST: scatter trunk/canopy structures at roughly the legacy 7.5% ground-
    cell density, adjusted downward only if 3D canopies make it unwalkable.
  - NEIGHBORHOOD: grid-aligned building placement (lot spacing) can be a later
    settled-biome variant, not a separate world or travel screen.
Keep v0 generation deliberately crude (correct, seeded, recognizable), not pretty.
Determinism per (world_seed, chunk) is mandatory (arch Issue 4).

Block palette to add (legacy tiles -> blocks): wall, floor (ground), tree, door
(openable). Reuse existing grass/stone/wood/dirt where sensible.

Start experience: legacy had a fixed starting room with a pistol. Reproduce near
world origin: a small starting structure, a pistol pickup, and the first enemies
placed at a minimum distance from spawn (legacy kept enemies >=8 units away and
out of the start room).

--------------------------------------------------------------------------------

render a brief tracer/muzzle flash. Flash a distinct hit marker only for an entity
hit. Do not show a shot when cooldown/equipment rejects it. Keep feedback cheap;
it is testing affordance, not polish.

--------------------------------------------------------------------------------
8. DEATH / RESTART  (align with arch respawn model)
--------------------------------------------------------------------------------
Legacy "game over -> Play Again -> fresh run". In a persistent continuous world,
reset = respawn the player (arch v0.2/v1), NOT wipe the world. On death: freeze
the survival timer, offer scorecard entry, respawn at the start structure with
starting kit. Keep the scorecard across respawns.

--------------------------------------------------------------------------------

Registries (behaviour-as-data): think routines ("hostile", "idle"), drop pools
("standard_enemy", ...), spawn routines (building-pickup, chunk-enemies), chunk
generators ("arena", "overworld"). All keyed by string, all serializable.
