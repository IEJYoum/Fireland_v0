  pistol        damage 20, projectile_speed 11,  lifetime 0.7

Decision (agent): keep the current hitscan Weapon for guns in v0 and treat

ship hitscan first (already works), add physical projectiles as a second weapon

closest_enemy_in_melee_arc as a 3D cone test.

Weapons as pickups spawn in the world with Transform+Pickup; equipping is the
existing interact path. Preserve "picking up a weapon auto-equips it."

--------------------------------------------------------------------------------
Add components + systems:
  Hunger(current, maximum)  decays 0.5/sec (HUNGER_LOSS_PER_SECOND). Eating food

Expose all three in the snapshot (per-component to_wire) and HUD.

3. ENEMIES  (direct-ish logic, 3D movement + aim)
--------------------------------------------------------------------------------
Rebuild the legacy behaviour as a registered Think routine ("hostile" or similar)
running on enemy entities that now have Velocity/Gravity/Grounded (arch Issue 3).

Behaviour to port (legacy enemies.py):
  - Only act when the enemy is in an active region (arch Issue 2 freeze replaces
    is_on_players_screen) AND has line-of-sight/path to a player.
  - Mode roll every 1.0s: 33% EVADE (pick a nearby reachable point, move there ~1s),
    else CHASE.
  - CHASE: if farther than preferred range, steer toward the player; else hold.
    preferred range: melee -> 0.75 * reach; ranged -> clamp(4..10, weapon_range/2).
  - Steering writes CONTROL velocity (speed ~2.4 u/s, ENEMY_SPEED) through the
    shared mover; physics handles collision/gravity.
  - Fire when within weapon range and off cooldown: aim at the player's eye in 3D
    with angular spread (legacy +-0.18 rad, apply in yaw and pitch), then
    hitscan or spawn a projectile. Cooldown random uniform(0.85, 1.3)s.
  - On death: grant player xp, roll the drop pool (section 4), remove entity.

Pathing: legacy used tile BFS (has_walkable_path). In 3D v0, DECISION for agent:
start with line-of-sight + direct steering (walk toward player if roughly visible,
let collision slide along walls). Real navmesh/pathfinding is deferred; do not
block the content rebuild on it.

Enemy stats: health 60 (legacy), holds a random weapon instance from the same
item system (reuse item defs). Enemy count / difficulty: legacy used
int(level_index**1.5)+1 per discrete map. With a continuous world, REINVENT as a
spawn-density model - e.g. spawn enemies per newly generated chunk, scaling count
or weapon tier with distance from origin. Keep it simple and seeded.

4. DROPS  (direct-ish odds, via the dormant Drops component + a registry)
--------------------------------------------------------------------------------
The Drops component exists but has no system - wire it now.
  - Add a drop-pool registry (behaviour-as-data): pool key -> routine(runtime,
    position, randomizer) that spawns the drop entity.
  - Port the legacy 1/3 odds pool: equal chance weapon / health_up / food.
    "weapon" drops the enemy's actual held weapon instance (legacy behaviour);
    health/food spawn fresh pickups.
  - Death handling (combat3d / a death system) reads Drops(pool=...) and invokes
    the pooled routine at the corpse position, then removes the entity.
This is also the seam for "cow drops turds", "boss drops key", etc. - new pools
are data.

Determinism: route drop rolls through a seeded randomizer owned by the runtime so
runs are reproducible (legacy had game.randomizer). Add one.

5. PICKUP MODEL  (reinvent - choose the interaction)
--------------------------------------------------------------------------------
Legacy: walking within 0.8 tiles auto-picks items; consumables auto-apply on
touch. Current 3D: aim at item + press E (ray interact).
DECISION for agent (recommend a hybrid):
  - Consumables (health_up): auto-apply on proximity (matches legacy feel).
  - Weapons/food: proximity auto-pickup into inventory, OR keep ray-interact.
Recommend proximity auto-pickup for everything, with inventory capacity 8 (legacy
INVENTORY_CAPACITY) and auto-equip weapons; drop ray-interact unless the owner
wants deliberate looting. Keep the chosen rule in one pickup system.

6. WORLD CONTENT: VOXEL MAP GENERATION  (reinvent - the big one)
--------------------------------------------------------------------------------
The legacy tile generators do not survive; their INTENT does. Rebuild as chunk
generators (arch Issue 4 provides the generator-by-key hook). Legacy map types
become generation flavours producing BLOCK structures:

  - Ground: flat (or gently varied) solid ground per chunk - the baseline.
  - PREFAB BUILDINGS: legacy placed hollow square/L footprints with wall borders,
    half with a door, 1/10 door-buildings holding a pickup. Rebuild as hollow
    block shells (walls + floor, open or doored), placed per chunk by seed, with
    a chance to spawn a pickup entity inside. A "door" is a block type that
    interaction can open (set_block to air) - port open_nearby_door as a block
    edit.
  - FOREST: scatter "tree" block columns at ~7.5% density on ground cells.
  - NEIGHBORHOOD: grid-aligned building placement (lot spacing) - a seed/placement
    variant of prefab.
Keep v0 generation deliberately crude (correct, seeded, recognizable), not pretty.
Determinism per (world_seed, chunk) is mandatory (arch Issue 4).

Block palette to add (legacy tiles -> blocks): wall, floor (ground), tree, door
(openable). Reuse existing grass/stone/wood/dirt where sensible.

Start experience: legacy had a fixed starting room with a pistol. Reproduce near
world origin: a small starting structure, a pistol pickup, and the first enemies
placed at a minimum distance from spawn (legacy kept enemies >=8 units away and
out of the start room).

8. DEATH / RESTART  (align with arch respawn model)
--------------------------------------------------------------------------------

reset = respawn the player (arch v0.2/v1), NOT wipe the world. On death: freeze
the survival timer, offer scorecard entry, respawn at the start structure with
starting kit. Keep the scorecard across respawns.
